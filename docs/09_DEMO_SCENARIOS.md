## 1. 시연 환경

### 1.1 하드웨어 구성

| 구성 요소 | 수량 | 배치 |
|-----------|------|------|
| 시뮬레이션 모형 | 1 | 밀폐공간 축소 재현 (약 2.5m x 2.0m x 1.5m) |
| 센서 노드 (Full-Spec) | 4 | 모형 내부 4곳 고정 배치 (UWB Anchor) |
| 웨어러블 노드 | 1 | 작업자 착용 (UWB Tag) |
| 관리자 대시보드 | 1 | 외부 모니터 (노트북 또는 디스플레이) |

### 1.2 소프트웨어 구성

| 구성 요소 | 설명 |
|-----------|------|
| MQTT Broker | Mosquitto (로컬 서버) |
| 백엔드 서버 | FastAPI (Python) |
| 시계열 DB | TimescaleDB |
| 웹 대시보드 | React 19 + TypeScript |
| 3D 디지털 트윈 | React Three Fiber + Three.js |

---

## 2. End-to-End 시연 흐름

```
센서 노드 전원 ON
→ 가스·온습도·O₂ 데이터 실시간 수집 및 MQTT 전송
→ 서버 수신·저장 및 임계값 비교
→ 위험 등급 판정 및 경보 발령
→ 웨어러블 진동 알림 전달
→ 대시보드 실시간 시각화 및 3D 디지털 트윈 표시
→ 시계열 데이터 조회 및 이벤트 로그 확인
```

## 3. 데모 시나리오 목록

### Scenario 1: 정상 상태 모니터링

| 항목 | 내용 |
|------|------|
| 목적 | 모든 센서가 정상 범위에서 동작함을 보인다 |
| 선행 조건 | 모든 노드 전원 ON, 네트워크 연결 완료 |
| 데이터 | 실제 센서 데이터 (정상 환경) |

**단계:**

1. 모든 센서 노드 전원 ON
2. 대시보드 접속 → 모든 노드 Online 표시 확인
3. 실시간 센서 값 카드 표시 확인 (CO₂, CO, H₂S, 온습도)
4. 3D 디지털 트윈에서 센서 마커 녹색 표시 확인
5. 웨어러블 노드 위치가 3D 공간에 표시되는지 확인

**성공 기준:**
- 모든 노드 Online 상태
- 모든 센서 값 정상 범위 표시
- 3D 트윈에 센서 마커와 작업자 위치 표시
- 카드 색상 녹색

### Scenario 2: 가스 농도 상승 경보

| 항목 | 내용 |
|------|------|
| 목적 | 가스 농도 상승 시 단계적 경보 발생을 보인다 |
| 선행 조건 | Scenario 1 완료 상태 |
| 데이터 | 소프트웨어 데이터 주입 (node_id: sim-01) |

**단계:**

1. 데이터 주입 클라이언트로 CO₂ 농도 데이터 publish
2. CO₂ = 1,200 ppm 주입 → Level 1 (주의) 경보 발생 확인
   - 대시보드 해당 노드 카드 노란색 변경
   - 3D 트윈 마커 노란색 변경
3. CO₂ = 2,500 ppm 주입 → Level 2 (경고) 경보 발생 확인
   - 카드 주황색 변경
   - 웨어러블 진동 알림 작동 (1초 진동 x 3회)
   - 이벤트 로그에 경보 기록
4. CO₂ = 5,500 ppm 주입 → Level 3 (위험) 경보 발생 확인
   - 카드 빨간색 변경
   - 대시보드 팝업 알림 및 사이렌
   - 웨어러블 연속 진동
5. CO₂ = 800 ppm 주입 → 경보 해제 확인 (Hysteresis 적용)
   - 5회 연속 1,900ppm 이하 확인 후 해제

**성공 기준:**
- 각 Level별 경보가 3초 이내 발생 (P95)
- 카드 색상 및 진동 패턴이 Level에 맞게 동작
- 3D 트윈 마커 색상 변경
- 이벤트 로그에 경보 발생/해제 기록

### Scenario 3: 작업자 위치 추적

| 항목 | 내용 |
|------|------|
| 목적 | 작업자 이동 시 실시간 위치 추적을 보인다 |
| 선행 조건 | UWB 앵커 보정 완료, Scenario 1 완료 상태 |
| 데이터 | 실제 UWB 측정 데이터 |

**단계:**

1. 작업자가 모형 내부에서 천천히 이동
2. 2D 대시보드에서 실시간 위치 표시 확인
3. 3D 디지털 트윈에서 작업자 아바타 이동 확인
4. 이동 궤적이 일정 시간 표시되는지 확인
5. 위험 구역(Level 2 경보 노드 반경 2m) 진입 시 추가 경보 확인

**성공 기준:**
- 위치 업데이트 빈도 5Hz 이상
- 3D 트윈에 작업자 위치 실시간 반영
- 위험 구역 진입 시 경보 발생

### Scenario 4: 낙상 감지

| 항목 | 내용 |
|------|------|
| 목적 | 작업자 낙상 시 즉각 경보 발생을 보인다 |
| 선행 조건 | Scenario 1 완료 상태 |
| 데이터 | 웨어러블 노드 가속도 데이터 |

**단계:**

1. 웨어러블 노드를 높은 위치에서 낙하 (또는 시뮬레이션)
2. 가속도 합성벡터 2.5g 이상 감지 확인
3. 1초 이상 정적 상태 감지 확인
4. Level 3 경보 즉시 발생 확인
   - 대시보드 팝업 알림
   - 웨어러블 연속 진동
5. 이벤트 로그에 낙상 감지 기록 확인

**성공 기준:**
- 낙상 감지 후 3초 이내 Level 3 경보 발생
- 대시보드 및 웨어러블 알림 정상 동작

### Scenario 5: O₂ 농도 저하

| 항목 | 내용 |
|------|------|
| 목적 | 작업자 주변 O₂ 농도 저하 시 경보 발생을 보인다 |
| 선행 조건 | Scenario 1 완료 상태 |
| 데이터 | 소프트웨어 데이터 주입 (wearable-01 vital 토픽) |

**단계:**

1. O₂ = 20.9% 정상 상태 확인
2. O₂ = 19.0% 주입 → Level 1 (주의) 경보
3. O₂ = 17.5% 주입 → Level 2 (경고) 경보 + 웨어러블 진동
4. O₂ = 15.0% 주입 → Level 3 (위험) 경보 + 연속 진동 + 팝업
5. O₂ = 20.9% 복귀 → 경보 해제

**성공 기능:**
- O₂ 임계값별 경보 정상 발생
- O₂ 센서 응답 시간(최대 15초) 고려하여 지연 가능성 명시
- 대시보드에 O₂ 농도 실시간 표시

> 주의: O₂ 경보는 센서 응답 시간으로 인해 3초 목표에서 제외된다.

## 4. 안전한 데이터 주입 방식

### 4.1 원칙

- 실제 유해 가스 사용 금지
- 모든 가스 농도 시나리오는 소프트웨어 기반 데이터 주입으로 시뮬레이션
- 데이터 주입은 MQTT 클라이언트를 통해 수행

### 4.2 주입 규칙

| 항목 | 규칙 |
|------|------|
| node_id | `sim-` prefix 사용 (예: `sim-01`) |
| 토픽 | 실제 센서와 동일한 토픽 구조 사용 |
| 페이로드 | `04_DATA_CONTRACT.md`의 Envelope 준수 |
| quality.calibrated | `true`로 설정 (경보 로직 테스트용) |
| quality.sensor_status | `stable`로 설정 |

### 4.3 주입 스크립트 구조

```
simulation/
├── scenarios/
│   ├── normal.json          # 정상 상태 데이터
│   ├── co2_warning.json     # CO₂ 상승 시나리오
│   ├── o2_low.json          # O₂ 저하 시나리오
│   └── multi_gas.json       # 복합 가스 시나리오
├── injector.py              # MQTT 데이터 주입 클라이언트
└── README.md                # 사용 방법
```

### 4.4 주의사항

- 주입 데이터는 대시보드에서 실제 센서와 시각적으로 구분 가능해야 한다
- `sim-` prefix 노드는 3D 트윈에서 점선 마커 또는 별도 색상으로 표시 권장
- 시연 종료 후 반드시 주입 노드의 데이터를 정리한다

## 2. 3D 디지털 트윈 기술 선택

**핵심 질문:** 3D 트윈이 "있으면 좋은 것"인지 "필수 핵심 기능"인지 먼저 합의 필요

| 옵션 | 장점 | 단점 |
|------|------|------|
| **Three.js** | 웹 기반, 러닝커브 낮음 | 물리 시뮬레이션 구현 어려움 |
| **Unity WebGL** | 물리엔진 내장, 시각적 완성도 높음 | 빌드 무겁고 Unity 경험 필요 |
| **Unreal Engine** | 가장 사실적인 렌더링 | 러닝커브 높음, 오버스펙 가능성 |
| **Grafana 대시보드** | 빠른 구현, 데이터 시각화 특화 | 3D 트윈 구현 불가 |

**논의 포인트**

## 3. AI 적용 범위

### A. 가스 확산 공간 분포도 추정

4개 노드 사이 빈 공간의 가스 농도를 수학적 보간으로 추정, 3D 트윈과 연결해 히트맵으로 시각화.

```
노드1[CO:45ppm]   ?   노드2[CO:12ppm]
       ?          ?          ?
노드3[CO:38ppm]   ?   노드4[CO:8ppm]
→ 보간으로 빈 공간 농도 추정
```

| 알고리즘 | 난이도 | 특징 |
|---------|--------|------|
| IDW (역거리 가중) | ★☆☆ | 구현 간단 |
| RBF (방사 기저 함수) | ★★☆ | scikit-learn 제공, 무난 |
| Kriging | ★★★ | 정확도 높음, 구현 복잡 |

> 시연 임팩트 가장 큼. ML 아닌 수학 보간이라 AI 전담자 없어도 구현 가능.

---

### B. 가스 농도 시계열 예측

현재 데이터 추세로 N분 후 농도 예측 → 위험 수준 도달 전 선제 경보.

```
현재까지:  100 → 150 → 230 → 380 → ???
예측:                              → 600 (5분 후 위험 수준 도달 예상)
```

| 알고리즘 | 난이도 | 특징 |
|---------|--------|------|
| 선형 회귀 | ★☆☆ | 단기 추세만, 초반 빠른 구현 |
| Prophet | ★★☆ | Facebook 오픈소스, 바로 사용 가능 |
| LSTM | ★★★ | 정확도 높음, 학습 데이터 많이 필요 |

> 초반엔 선형 회귀로 시작 → 데이터 쌓이면 LSTM 업그레이드 전략 추천.

---

### C. 낙상 감지 고도화

현재 PRD 방식(합성 가속도 ≥ 2.5g + 1초 정적)을 ML 분류 모델로 교체해 오탐 감소.

| 방식 | 장점 | 단점 |
|------|------|------|
| 임계값 (현재) | 구현 완료 | 앉기/뛰기 오탐 많음 |
| SVM / Random Forest | 오탐 감소 | 직접 데이터 수집 필요 |
| TensorFlow Lite (엣지) | WiFi 없어도 동작 | 모델 크기 제한, 구현 복잡 |

**구현 순서**
1. MPU-6050으로 낙상/정상 동작 데이터 직접 수집 (팀원이 직접 넘어지며 수집)
2. SVM 또는 Random Forest로 분류 모델 학습
3. 서버 판단 or ESP32 엣지 AI 결정

**논의 포인트**
- [ ] 엣지(ESP32 직접 판단) vs 서버 판단 결정
- [ ] 학습 데이터 수집 담당자 확정

---

### D. 이상 감지 (Anomaly Detection)

정상 패턴을 학습시키고, 임계값 안 넘어도 패턴 이탈 시 자동 감지.

```
정상 패턴: CO2 800, CO 10, H2S 0.5 가 함께 움직임
이상 감지: CO2는 정상인데 H2S만 급등 → 특정 구역 누출 의심
```

| 알고리즘 | 특징 |
|---------|------|
| Isolation Forest | 구현 쉬움, scikit-learn 제공 |
| Z-score | 가장 단순, 개별 센서 이상만 감지 |
| Autoencoder | 정확도 높음, 구현 복잡 |

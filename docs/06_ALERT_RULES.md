| 항목 | 내용 |
|------|------|
| 문서명 | 경보 판정 규칙서 |
| 버전 | v2.0 |

| 최종 수정일 | 2026-07-13 |

---

## 1. 개요

본 문서는 센서 측정값을 기반으로 위험 등급을 판정하고 경보를 발령/해제하는 규칙을 정의한다.

### 핵심 원칙

1. **경보는 실제 센서 측정값으로만 판정한다.** IDW 공간 보간 추정값은 경보에 사용하지 않는다. (ADR-005)
2. **시간 기반 판정을 사용한다.** 발행 주기가 다른 센서에 대해 횟수 기반("N회 연속") 대신 시간 기반(밀리초 지속) 판정을 적용한다.
3. **Hysteresis를 적용한다.** 경보 발생과 해제 기준을 분리하여 플리커링을 방지한다.
4. **단계적 승격 및 단계적 해제를 적용한다.** 경고 해제 시 한 단계씩만 하향한다.
5. **O2 센서 응답 시간을 별도 관리한다.** SEN0322 응답 시간(최대 15초)과 시스템 전송 지연(P95 3초)을 분리한다.
6. **임계값은 하드코딩하지 않는다.** DB 또는 설정 파일에서 관리한다.

## 2. 위험 등급 정의

| 등급 | 식별자 | 색상 | 의미 |
|------|--------|------|------|
| 정상 | `normal` | 초록 | 모든 측정값이 정상 범위 |
| Level 1 | `level1_caution` | 노랑 | 주의. 모니터링 강화 권장 |
| Level 2 | `level2_warning` | 주황 | 경고. 웨어러블 진동 알림 작동 |
| Level 3 | `level3_critical` | 빨강 | 위험. 대피 권장. 대시보드 팝업 + 사이렌 |

## 3. 시간 기반 판정 규칙

### 3.1 횟수 기반 판정의 문제

센서마다 MQTT 발행 주기가 다르다 (CO2: 1초, BME680: 5초, O2: 5초). "3회 연속" 기반 판정은 주기별로 실제 대기 시간이 달라진다 (CO2는 3초, O2는 15초). 따라서 모든 센서에 **시간 기반(duration)** 판정을 적용한다.

### 3.2 시간 기반 판정 파라미터

각 경보 규칙은 다음 파라미터로 정의된다.

| 파라미터 | 설명 |
|-----------|------|
| `enter_threshold` | 경보 진입 임계값 |
| `enter_for_ms` | 진입 조건 지속 시간 (밀리초). 이 시간 동안 조건이 연속으로 유지되면 경보 발령 |
| `exit_threshold` | 경보 해제 임계값 (Hysteresis) |
| `exit_for_ms` | 해제 조건 지속 시간 (밀리초). 이 시간 동안 조건이 연속으로 유지되면 경보 해제 |

### 3.3 단계적 승격 및 해제

**승격 (Escalation):**

임계값 초과 시 즉시 상위 등급으로 승격한다. 단, `enter_for_ms` > 0인 경우 해당 시간 동안 조건이 유지되어야 한다.

```
Normal → Level 1 → Level 2 → Level 3
```

**해제 (De-escalation):**

한 번에 한 단계씩만 하향한다. Level 3에서 정상으로 즉시 복귀하지 않는다.

```
Level 3 → Level 2 → Level 1 → Normal
```

> 단계적 해제는 위험 상황이 급격히 호전되더라도 신중한 판단을 유지하기 위함이다. 각 단계마다 `exit_for_ms` 시간 동안 조건이 유지되어야 다음 단계로 하향한다.

## 4. 가스 농도 임계값

### 4.1 교정 완료 센서 임계값

다음 표는 `enter_threshold` 값이다. `exit_threshold`는 Hysteresis 값을 뺀 값이다.

#### CO2 (MH-Z19B)

| 등급 | enter_threshold (ppm) | enter_for_ms | exit_threshold (ppm) | exit_for_ms |
|------|-----------------------|--------------|----------------------|-------------|
| Level 1 | >= 1000 | 3000 | < 900 | 5000 |
| Level 2 | >= 2000 | 3000 | < 1900 | 5000 |
| Level 3 | >= 5000 | 0 (즉시) | < 4500 | 5000 |

#### CO (MQ-7, 교정 후)

| 등급 | enter_threshold (ppm) | enter_for_ms | exit_threshold (ppm) | exit_for_ms |
|------|-----------------------|--------------|----------------------|-------------|
| Level 1 | >= 25 | 3000 | < 20 | 5000 |
| Level 2 | >= 50 | 3000 | < 45 | 5000 |
| Level 3 | >= 200 | 0 (즉시) | < 180 | 5000 |

#### H2S (MQ-136, 교정 후)

| 등급 | enter_threshold (ppm) | enter_for_ms | exit_threshold (ppm) | exit_for_ms |
|------|-----------------------|--------------|----------------------|-------------|
| Level 1 | >= 1 | 3000 | < 0.5 | 5000 |
| Level 2 | >= 5 | 3000 | < 4 | 5000 |
| Level 3 | >= 10 | 0 (즉시) | < 8 | 5000 |

#### 온도 (BME680)

| 등급 | enter_threshold (C) | enter_for_ms | exit_threshold (C) | exit_for_ms |
|------|---------------------|--------------|---------------------|-------------|
| Level 1 | >= 35 | 5000 | < 34 | 10000 |
| Level 2 | >= 38 | 5000 | < 37 | 10000 |
| Level 3 | >= 40 | 0 (즉시) | < 39 | 10000 |

### 4.2 O2 (SEN0322) — 양방향 임계값

O2는 저농도(Oxygen Depletion)와 고농도(Oxygen Enrichment) 양쪽 모두 위험하다. 따라서 bidirectional hysteresis를 적용한다.

#### O2 저농도 (Oxygen Depletion)

| 등급 | enter_threshold (%) | enter_for_ms | exit_threshold (%) | exit_for_ms |
|------|---------------------|--------------|---------------------|-------------|
| Level 1 | < 19.5 | 5000 | >= 20.0 | 10000 |
| Level 2 | < 18.0 | 5000 | >= 18.5 | 10000 |
| Level 3 | < 16.0 | 0 (즉시) | >= 16.5 | 10000 |

#### O2 고농도 (Oxygen Enrichment)

| 등급 | enter_threshold (%) | enter_for_ms | exit_threshold (%) | exit_for_ms |
|------|---------------------|--------------|---------------------|-------------|
| Level 1 | > 23.5 | 5000 | <= 23.0 | 10000 |
| Level 2 | > 25.0 | 5000 | <= 24.5 | 10000 |
| Level 3 | > 28.0 | 0 (즉시) | <= 27.5 | 10000 |

> O2 경보는 저농도와 고농도를 독립적으로 추적한다. `alert_key`는 `o2_low`와 `o2_high`로 구분된다.

### 4.3 교정 전 센서 처리 (MVP 정책)

MQ-7, MQ-136, MQ-2 센서는 MVP 기간 동안 **raw 값만 제공**한다. 임계값 기반 경보에서 제외한다.

| 센서 | MVP 정책 | 비고 |
|------|---------|------|
| MQ-7 (CO) | raw 데이터만 표시, 경보 제외 | 교정에는 알려진 농도의 CO 가스가 필요하나, 본 프로젝트에서는 실제 유해 가스 사용 금지 |
| MQ-136 (H2S) | raw 데이터만 표시, 경보 제외 | 동일 |
| MQ-2 | raw 데이터만 표시, 경보 제외 | 동일 |
| BME680 gas_resistance | 추세 모니터링만, 경보 제외 | — |

> CO 및 H2S 경보 파이프라인은 **소프트웨어 데이터 주입**(`source_mode: "simulation"`)으로만 검증한다. 실제 센서 기반 CO/H2S 경보는 교정 환경이 확보된 후 활성화한다.

### 4.4 BME680 IAQ 지수 참고 기준

> 아래 기준은 참고용이며, BSEC 라이브러리의 iaq_accuracy가 2 이상일 때만 유효하다. 경보를 발령하지 않는다.

| IAQ | 범위 | 공기질 |
|-----|------|--------|
| 0-50 | 우수 | 청결한 공기 |
| 51-100 | 보통 | 대부분의 실내 환경 |
| 101-150 | 다소 불량 | 환기 권장 |
| 151-200 | 불량 | 환기 필요 |
| 201+ | 매우 불량 | 오염 의심 |

### 4.5 임계값 설정 파일 형식 (YAML)

```yaml
alert_rules:
  co2_ppm:
    sensor: "mh-z19b"
    levels:
      level1_caution:
        enter_threshold: 1000
        enter_for_ms: 3000
        exit_threshold: 900
        exit_for_ms: 5000
      level2_warning:
        enter_threshold: 2000
        enter_for_ms: 3000
        exit_threshold: 1900
        exit_for_ms: 5000
      level3_critical:
        enter_threshold: 5000
        enter_for_ms: 0
        exit_threshold: 4500
        exit_for_ms: 5000

  o2_low:
    sensor: "sen0322"
    direction: "below"
    levels:
      level1_caution:
        enter_threshold: 19.5
        enter_for_ms: 5000
        exit_threshold: 20.0
        exit_for_ms: 10000
      # ...

  o2_high:
    sensor: "sen0322"
    direction: "above"
    levels:
      level1_caution:
        enter_threshold: 23.5
        enter_for_ms: 5000
        exit_threshold: 23.0
        exit_for_ms: 10000
      # ...
```

## 5. 낙상 감지 규칙

### 5.1 감지 조건

```
단계 1: 합성 가속도 벡터 |a| >= 2.5g 감지 (충격 감지)
단계 2: 1초 이내 |a| 변화량이 임계값 초과 (급감속)
단계 3: 이후 1초 이상 |a|가 정적 상태 (0.9g ~ 1.1g 범위) 지속
-> 낙상으로 판정
```

### 5.2 경보 발령

- 낙상 판정 시 **즉시 Level 3 경보** 발령
- 시간 기반 지속 조건 없이 1회 판정으로 즉시 발령

### 5.3 오감지 처리

- **MAY**: 작업자가 오감지 취소 버튼을 눌러 경보를 해제할 수 있다
- 취소된 낙상 경보는 이벤트 로그에 `false_positive` 태그로 기록된다

## 6. O2 경보 지연 분리

### 6.1 지연 성분 분리

O2 경보 지연은 두 가지 독립적인 성분으로 분리하여 관리한다.

| 지연 성분 | 정의 | 목표 | 비고 |
|-----------|------|------|------|
| 센서 응답 시간 | 실제 O2 농도 변화 → SEN0322 측정값 반영 | <= 15초 (센서 사양) | 보장 불가, 센서 물리적 한계 |
| 시스템 전송 지연 | sampled_at → 대시보드/진동 표시 | P95 <= 3초 | MQTT + 백엔드 + WebSocket |

### 6.2 대시보드 표시

- O2 경보 카드에 "센서 응답 지연 가능성 (최대 15초)" 라벨 표시
- O2 경보는 가스 경보와 시각적으로 구분 (별도 아이콘)

### 6.3 O2 경보 단독 운용

MVP에서는 O2 단독 임계값 경보만 적용한다. 복합 위험 점수에 O2가 포함되더라도 단독 경보가 우선한다.

## 7. 위험 구역 진입 경보

### 7.1 위험 구역 정의

- Level 2 이상 경보가 발령된 센서 노드를 중심으로 하는 **원형 영역**
- 기본 반경: **0.5m** (설정 파일에서 변경 가능)
- 디지털 트윈 상에서 해당 영역을 반투명 색상으로 표시

> 기본 반경 0.5m는 축소 데모 공간(`demo-local`)에서의 경보 판정 기준이다. 선박형
> 3D 트윈 표시 공간은 60m x 20m x 14m(`ship-visual`)이며, 화면에 표시할 때는
> 중심 좌표와 영역 크기를 동일한 좌표 변환 규칙으로 변환한다. 경보 판정은 원본
> 좌표계 기준 거리로 수행하고, 화면 표시는 `ship-visual` 좌표계임을 명시한다.

### 7.2 진입 감지

- 웨어러블 노드의 UWB 위치가 위험 구역 경계 내로 진입할 때 추가 경보 발령
- 위험 구역 진입 경보는 Level 2로 발령
- 위험 구역 이탈 시 자동 해제

### 7.3 위험 구역 기하 정보

```json
{
  "type": "circle",
  "center_node_id": "sensor-01",
  "center_position": { "x_m": 0.5, "y_m": 0.3 },
  "radius_m": 0.5,
  "trigger_level": "level2_warning"
}
```

> 위험 구역은 2D 바닥 평면상의 원형으로 정의한다. 작업자 위치의 z_m(항상 0.0)과 동일한 평면에서 거리를 계산한다.

## 8. 경보 알고리즘 단계

### 8.1 1단계: 임계값 기반 (MUST)

```
입력: 센서 측정값
처리:
  1. 임계값 비교 (enter_threshold)
  2. 시간 기반 지속 확인 (enter_for_ms)
  3. Hysteresis 기반 단계적 해제 (exit_threshold + exit_for_ms)
출력: 경보 상태 (active / resolved)
```

### 8.2 2단계: 추세 기반 (SHOULD)

```
입력: 최근 N개 측정값
처리:
  1. 이동 평균 (window: 30초)
  2. 선형 회귀 기울기 계산
  3. EWMA (Exponentially Weighted Moving Average)
출력: 상승 추세 표시 (대시보드에 경고 배지)
```

> 추세 경고는 독립적인 경보를 발령하지 않고, 대시보드에 시각적 표시만 제공한다.

### 8.3 3단계: LSTM 예측 (MAY / Research Track)

```
입력: 과거 60초 시계열 데이터
처리:
  1. LSTM 모델로 5분 후 농도 예측
  2. 예측값이 위험 임계값 도달 예상 시 선제 경고
출력: 예측 기반 선제 경고
```

> LSTM은 충분한 실험 데이터가 확보된 후 별도 실험으로 평가한다. MVP의 MUST가 아니다.
> 학습 데이터 규모, 누출 시나리오 종류, Train/Validation/Test 분할 기준이 정의되기 전까지 모델 구조를 확정하지 않는다.

## 9. 복합 위험 점수 (참고 지표)

> 복합 위험 점수는 **실험 검증 전까지 참고 지표로만 사용**한다. 안전 경보의 단독 근거로 사용하지 않는다.

### 공식

```
Total Risk Score = (S_O2 * 0.35) + (S_Gas * 0.30) + (S_Env * 0.10) + (S_Worker * 0.25)
```

| 변수 | 설명 |
|------|------|
| S_O2 | 산소 농도 감점 점수 (정상 20.9% 기준 이탈 시 감점) |
| S_Gas | 유해가스 복합 지수 (CO, H2S, 가스저항 정규화 가중합) |
| S_Env | BME680 기반 온/습도 열지수 점수 |
| S_Worker | MPU-6050 및 낙상 이상 징후 매핑 점수 |

### 등급 매핑 (참고)

| 점수 | 등급 |
|------|------|
| < 40 | SAFE |
| 40 - 59 | CAUTION |
| 60 - 79 | WARNING |
| >= 80 | CRITICAL |

> 위 가중치(0.35/0.30/0.10/0.25)와 컷오프(40/60/80)는 검증 근거가 없다. 실험 데이터 누적 후 조정한다.

## 10. 경보 발행 규칙

### 10.1 발행 주체 및 토픽

| 경보 유형 | 발행 주체 | 이벤트 토픽 | 상태 토픽 (alert_key) |
|-----------|---------|------------|----------------------|
| 가스 임계값 | 백엔드 서버 | `alerts/events/{node_id}` | `alerts/state/{node_id}/co2_ppm` |
| 낙상 감지 | 백엔드 서버 | `alerts/events/wearable-01` | `alerts/state/wearable-01/fall_detection` |
| O2 저농도 | 백엔드 서버 | `alerts/events/wearable-01` | `alerts/state/wearable-01/o2_low` |
| O2 고농도 | 백엔드 서버 | `alerts/events/wearable-01` | `alerts/state/wearable-01/o2_high` |
| 위험 구역 진입 | 백엔드 서버 | `alerts/events/wearable-01` | `alerts/state/wearable-01/zone_intrusion` |
| 연결 끊김 | 백엔드 서버 | `alerts/events/{node_id}` | `alerts/state/{node_id}/connection_lost` |

> 토픽 구조 상세는 `04_DATA_CONTRACT.md` 섹션 3.4 참조.

### 10.2 Retain 정책

- `alerts/events/{node_id}`: Retain 사용 안 함. 경보 발생/해제 이벤트를 순차적으로 스트리밍.
- `alerts/state/{node_id}/{alert_key}`: Retain 사용. alert_key별 현재 경보 상태 유지. 경보 해제 시 해당 key의 Retain 메시지를 `status: "resolved"`로 업데이트.
- 대시보드 재연결 시 모든 `alerts/state/#` Retain 메시지를 읽어 활성 경보 목록을 복구.

### 10.3 지연 목표

> P95 3초 목표는 **시스템 전송 지연**(경보 판정 완료 T4부터)에만 적용된다. `enter_for_ms`(탐지 지연)는 오탐 방지용 의도적 지연이므로 별도 관리한다. 상세는 섹션 6.1 참조.

| 경보 유형 | P95 목표 | 측정 구간 | 비고 |
|-----------|---------|-----------|------|
| 가스 임계값 | <= 3초 | T4(판정완료) → T6(진동) | 시스템 전송 지연 |
| 낙상 감지 | <= 3초 | T0(sampled_at) → T7(UI) | enter_for_ms 없음 (즉시 발령) |
| O₂ 저/고농도 | <= 3초 (시스템 전송) | T4 → T6 | 센서 응답 시간(최대 15초)은 별도 관리 |
| 위험 구역 진입 | <= 3초 | 위치 업데이트 → 경보 | zone_intrusion alert_key |

> 실험 연결: EXP-4 (End-to-End 경보 지연). T4→T6(시스템 전송)과 T0→T6(총 지연)을 분리하여 측정한다.

## 11. 진동 패턴

| 위험 등급 | 진동 패턴 | 모터 제어 |
|-----------|-----------|-----------|
| Level 1 (주의) | 0.5초 진동 x 2회 | 짧은 펄스 2회 |
| Level 2 (경고) | 1초 진동 x 3회, 반복 | 1초 펄스 3회 후 2초 대기, 반복 |
| Level 3 (위험) | 연속 진동 | 중단 없이 연속 구동 |

### 진동 모터 회로 (NPN Low-Side Switch)

```
+5V 레일
  |
  진동 모터 (+) 단자
  |
  진동 모터 (-) 단자
  |
  S8050 NPN 트랜지스터 Collector (C)
  |
  S8050 NPN 트랜지스터 Emitter (E) --------- GND
  |
  S8050 NPN 트랜지스터 Base (B)
  |
  1kΩ 베이스 저항
  |
  ESP32 GPIO25

1N4007 다이오드:
  Cathode (음극, 띠 표시) --------- +5V 레일
  Anode (양극) --------- Collector (모터 (-) 단자와 트랜지스터 C 사이)
```

> NPN 트랜지스터는 low-side switch로 동작한다. 모터는 +5V와 Collector 사이에 연결하고, Emitter는 GND에 연결한다. 다이오드는 모터 양단에 역병렬(역기전력 보호)로 설치한다: Cathode를 +5V측, Anode를 Collector(모터 하단)측에 연결한다.
>
> 이전 문서의 "Collector -> +5V, Emitter -> 모터" 배선은 잘못되었다. NPN low-side 구동에서는 모터가 +5V와 Collector 사이에 위치해야 한다.

## 12. 로컬 폴백 경보 (웨어러블 자율 경보)

> **Safety-Critical**: 백엔드 또는 MQTT 브로커 장애 시에도 작업자 안전 경보가 동작해야 한다.

### 12.1 배경

기본 경보 흐름은 센서 → MQTT → 백엔드(임계값 판정) → MQTT → 웨어러블(진동)이다. 이는 백엔드나 MQTT 브로커가 장애 시 경보가 전달되지 않는 단일 장애점(SPOF)을 가진다.

### 12.2 웨어러블 로컬 O₂ 임계값 검사

웨어러블 노드는 자체 O₂ 센서(SEN0322) 데이터에 대해 **펌웨어 내 로컬 임계값 검사**를 수행한다. 백엔드 통신 상태와 무관하게 동작한다.

| 조건 | 동작 |
|------|------|
| O₂ < 16.0% (Level 3 저농도) | 즉시 연속 진동 (백엔드 통신 무관) |
| O₂ > 28.0% (Level 3 고농도) | 즉시 연속 진동 (백엔드 통신 무관) |

- 로컬 임계값은 펌웨어에 하드코딩한다 (백엔드 장애 시 설정을 조회할 수 없으므로).
- 로컬 경보 발생 시 웨어러블은 `wearable/{node_id}/vital` 메시지에 `local_alert: true` 플래그를 포함한다.
- 백엔드 정상화 후 백엔드 경보와 로컬 경보가 중복될 수 있다. 이는 허용한다 (안전 측 우선).

### 12.3 낙상 감지 로컬 처리

낙상 감지(FR-202)는 펌웨어 내에서 처리되므로 이미 로컬 동작한다. 백엔드 장애와 무관하게 Level 3 경보를 발령한다.

## 13. 클럭 동기화 실패 시 처리

시간 기반 경보 판정(enter_for_ms / exit_for_ms)은 정확한 타임스탬프에 의존한다. 노드의 `quality.time_synced == false`인 경우 (NTP 동기화 실패):

1. 백엔드는 `backend_received_at`을 타임스탬프 대신 사용한다 (수신 시각 기준).
2. `time_synced: false` 경고를 대시보드에 표시한다.
3. 경보 판정은 계속 수행하되, 타이밍 정확도가 낮음을 로그에 기록한다.

> 이 fallback은 1줄 조건문으로 구현 가능하다: `if (not quality.time_synced): timestamp = backend_received_at`

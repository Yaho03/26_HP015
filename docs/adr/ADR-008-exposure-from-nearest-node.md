# ADR-008: 작업자 누적 노출량은 최근접 노드 실측값으로 산정한다

| 항목 | 내용 |
|------|------|
| 상태 | Proposed |
| 결정일 | 2026-08-21 |
| 결정자 | — (검토 필요) |
| 관련 | ADR-005, FR-701~707, `11_EXPOSURE_DOSE_SPEC.md` |

## 배경

작업자 누적 유해가스 노출량(dose)을 계산하려면 **작업자가 있는 위치의 농도** C(t)가 필요하다. 그런데 현재 하드웨어 구성에서 웨어러블 노드가 직접 측정하는 가스는 **O₂ 하나뿐이다**. CO₂·CO·H₂S는 고정 센서 노드 4개에만 있다.

따라서 작업자 위치의 가스 농도는 측정값이 아니라 **추정값**이 될 수밖에 없다. 문제는 ADR-005가 "IDW 추정값을 경보 판정에 사용하지 않는다"고 못박았다는 것이다. 누적 노출량 경보도 경보이므로 이 결정과 정면으로 충돌한다.

## 결정

노출량 산정 농도 `exposure_concentration`은 **작업자 최근접 센서 노드의 실측값**을 사용한다. IDW 보간값은 사용하지 않는다.

| 가스 | `exposure_source` | 근거 |
|------|-------------------|------|
| O₂ | `wearable_direct` | 웨어러블이 직접 측정. 진짜 작업자 값이다 |
| CO₂ | `nearest_node` | MH-Z19B 실측 ppm. 최근접 노드 값을 대입 |
| CO / H₂S | `unavailable` | MQ-7·MQ-136 미교정 → ppm 없음 (ALERT_RULES §4.3) |

동시에 **보수적 참고값**으로 `dose_worst_case_ppm_min`(전 노드 최댓값 기준 누적)을 함께 계산해 대시보드에 병기한다. 경보는 `nearest_node` 기준으로만 발령하고, worst-case는 표시 전용이다.

거리 정보는 숨기지 않는다. 페이로드에 `source_node_id`와 `source_distance_m`을 항상 싣고, 대시보드는 거리가 `exposure.max_trust_distance_m`(기본 3.0m)를 넘으면 "추정 신뢰도 낮음" 배지를 띄운다.

## 대안

| 대안 | 결과 | 이유 |
|------|------|------|
| 최근접 노드 실측값 | 채택 | 실측값이므로 ADR-005 훼손 없음. 거리를 함께 노출해 한계가 화면에 드러남 |
| IDW 보간값 | 기각 | ADR-005 위반. 검증되지 않은 추정값이 누적되면 오차도 누적된다 — 순간값보다 오히려 위험 |
| 전 노드 최댓값으로 경보 | 기각 | 4개 노드 중 하나만 높아도 반대편 작업자에게 경보 → 오경보 과다로 경보 자체가 무시됨 |
| 웨어러블에 가스 센서 추가 | 향후 | 가장 정확하나 하드웨어 확보·전원·크기 문제. MVP 범위 초과 |

## 결과

**긍정:**
- ADR-005의 "측정값 = 경보, 추정값 = 시각화" 경계가 그대로 유지된다
- MQ 교정이 끝나면 CO·H₂S가 코드 변경 없이 자동 활성화된다 (`calibration_status` 기반 분기)
- `source_distance_m`이 화면에 나오므로 심사자가 한계를 직접 확인할 수 있다

**부정:**
- 작업자가 노드 사이 중간에 있으면 실제 노출 농도와 차이가 난다. 이 오차는 정량화되지 않았다
- 위치(UWB)가 끊기면 최근접 노드를 결정할 수 없다 → `exposure_source: "unavailable"`로 떨어지고 누적이 멈춘다. 이 공백은 `data_gap_s`로 기록하고 화면에 표시해야 한다
- CO·H₂S는 MVP 기간 내내 `null`이다. 파이프라인은 동작하지만 값이 없다

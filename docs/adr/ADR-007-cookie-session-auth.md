# ADR-007: 쿠키 세션 기반 인증 (JWT 아님)

| 항목 | 내용 |
|------|------|
| 상태 | 채택 (2026-08-20) |
| 관련 | FR-601~611 (PRD §4.6), 이슈 #131~#142, #116 |

## 배경

임계값·작업자 생체·위치 데이터를 다루는 안전 시스템이 인증 없이 공개돼
있었다 (#116 — 무인증 PUT /api/thresholds). 인증 도입 시 토큰 저장 위치와
WebSocket 인증 방식이 근본 설계 결정이다.

## 결정

**서버 세션 + HttpOnly 쿠키**를 쓴다. JWT-in-localStorage는 채택하지 않는다.

## 근거

1. **WebSocket 핸드셰이크 제약** — 브라우저 WebSocket API는 커스텀 헤더를
   붙일 수 없다. JWT라면 토큰을 쿼리 파라미터나 첫 메시지로 보내야 하는데,
   쿼리 파라미터는 액세스 로그·프록시 로그에 남아 토큰 유출 경로가 된다.
   쿠키는 핸드셰이크에 자동 포함되므로 이 문제가 없다.
2. **즉시 폐기 가능성** — 세션은 서버 저장이라 로그아웃/계정 잠금 즉시
   무효화된다. JWT는 서명 검증만 하면 만료까지 살아 있어, "경보 상황에서
   권한 회수"가 늦어진다. 안전 시스템에서는 회수 지연이 위험이다.
3. **XSS 토큰 유출 차단** — HttpOnly 쿠키는 JavaScript에서 읽을 수 없다.
   localStorage JWT는 XSS 한 번이면 만료까지 탈취된다.

## 트레이드오프와 대응

| 비용 | 대응 |
|------|------|
| CSRF 공격면 증가 (쿠키 자동 송부) | double-submit 토큰 (FR-608), SameSite=Lax |
| 세션 저장소 운영 (DB) | sessions 테이블 + 주기 정리 태스크 (FR-611) |
| DB 유출 시 세션 탈취 가능 | session_id는 SHA-256 해시로만 저장 (원문 미보관) |
| 세션 만료가 경보를 가릴 수 있음 | 경보 가시성 우선 규칙 (FR-607, §08 1.5) — 로그인 오버레이 + 유휴 타이머 연장 |

## 역할 모델 (RBAC)

| 동작 | admin | supervisor | viewer |
|------|:-----:|:----------:|:------:|
| 대시보드/WS/GET thresholds | ✅ | ✅ | ✅ |
| PUT thresholds | ✅ | ❌ | ❌ |
| 경보 ack / CSV export / 작업자 CRUD | ✅ | ✅ | ❌ |
| 사용자 CRUD / 감사로그 / metrics | ✅ | ❌ | ❌ |

## 결과

- 로그인/로그아웃/만료의 의미가 서버에서 명확해진다.
- WebSocket은 accept() 이전에 쿠키를 검증하고, 실패 시 close 1008.
- 프론트는 `credentials: "include"`로 쿠키를 전달하고 401 인터셉터로
  로그인 오버레이를 띄운다 (전체 전환 금지 — FR-607).

# ADR-003: 3D 디지털 트윈 기술 Three.js 확정

| 항목 | 내용 |
|------|------|
| 상태 | Accepted |
| 결정일 | 2026-07-13 |
| 결정자 | 팀 합의 |

## 배경

TEAM_DISCUSSION에서 Three.js, Unity WebGL, Unreal Engine, Grafana를 비교 검토했다. 본 프로젝트의 3D 요구사항은 물리 시뮬레이션이 아닌 다음 기능에 집중되어 있다: glTF 공간 표시, 센서 마커, 작업자 이동, 위험도 색상 표시, Heatmap, 웹 대시보드와 상태 공유. React 대시보드와 별도 애플케이션으로 연결하는 것보다 단일 웹 애플리케이션으로 통합하는 것이 유지보수에 유리하다.

## 결정

React Three Fiber(R3F) + Three.js를 채택한다. 3D 모델은 Blender로 제작 후 glTF/GLB 형식으로 export한다. 1 Three.js unit = 1 meter.

## 대안

| 대안 | 결과 | 이유 |
|------|------|------|
| Three.js / R3F | 채택 | 웹 기반, React 통합 용이, 러닝커브 낮음, 단일 애플리케이션 |
| Unity WebGL | 기각 | 빌드 무거움, React와 별도 애플리케이션 연결 복잡, Unity 경험 필요 |
| Unreal Engine | 기각 | 오버스펙, 러닝커브 높음, 웹 배포 복잡 |
| Grafana | 기각 | 3D 트윈 구현 불가, 시계열 대시보드 전용 |

## 결과

**긍정:**
- React 생태계와 자연스러운 통합 (상태 공유, 컴포넌트 재사용)
- 웹 표준 기술 (WebGL), 별도 플러그인 불필요
- 유지보수 단순 (단일 프론트엔드 코드베이스)
- 풍부한 커뮤니티와 학습 자료

**부정:**
- 물리 시뮬레이션 기능 제한적 (본 프로젝트에서 불필요)
- 대규모 씬 최적화 필요 시 추가 작업 (본 프로젝트 규모에서는 문제 없음)

## 0. 문서 사용 규칙

### 0.1 요구사항 강도

| 표현 | 의미 |
|------|------|
| MUST | MVP 구현에 필수. 미구현 시 MVP 성공 기준을 충족하지 못한다. |
| SHOULD | MVP에 포함하는 것을 원칙으로 하되, 일정상 조정 가능하다. |
| MAY | 선택 구현 또는 향후 확장이다. |
| OUT OF SCOPE | MVP에서 제외한다. |

### 0.2 요구사항 ID 규칙

모든 기능 요구사항에는 `FR-XXX` 형태의 ID를 부여한다. 각 ID는 실험 계획서(`07_EXPERIMENT_PLAN.md`)의 Test ID와 연결된다.

1. 본 `01_PRD.md`
2. `04_DATA_CONTRACT.md` (MQTT 페이로드 스키마)

본 시스템은 **작업자 안전을 보조하는 모니터링·경보 도구**이다. 최종 대피 판단 및 작업 중지 결정은 현장 관리자에게 있으며, 본 시스템의 경보가 공식 산업안전보건 기준을 대체하지 않는다. 상세한 면책 및 센서 신뢰성 제한은 `08_SAFETY_AND_LIMITATIONS.md`를 참조한다.

## 1. 제품 정의

### 1.1 제품 개요

조선소 밀폐공간(탱크 내부, 이중저 구획 등) 작업 시 발생할 수 있는 유해가스 누출, 산소 결핍, 낙상 위험을 실시간으로 감지하고 관리자 및 작업자에게 즉각 경보를 제공하는 IoT 기반 안전 모니터링 시스템이다.

센서 노드가 수집한 시계열 데이터는 MQTT를 통해 서버로 전송되고, 관리자는 웹 대시보드에서 실시간 환경 현황 및 3D 디지털 트윈 시각화를 통해 밀폐공간 내부 상황을 확인한다.

### 1.2 MVP 목표 흐름

MVP는 다음 흐름을 한 번에 시연할 수 있어야 한다.

```
센서 노드 전원 ON
→ 가스·온습도·O₂ 데이터 실시간 수집 및 MQTT 전송
→ 서버 수신·저장 및 임계값 비교
→ 위험 등급 판정 및 경보 발령
→ 웨어러블 진동 알림 전달
→ 대시보드 실시간 시각화 및 3D 디지털 트윈 표시
→ 시계열 데이터 조회 및 이벤트 로그 확인
```

### 1.3 제품 성공 정의

| 성공 항목 | 정의 | 관련 실험 |
|-----------|------|-----------|
| 수집 가능성 | 센서 노드 4개가 CO₂·CO·H₂S·가스저항·온습도를 동시 수집하여 대시보드에 표시 | EXP-1 |
| 경보 가능성 | 임계값 초과 시 3초 이내에 경보가 발령되고 웨어러블 진동이 작동 (O₂ 제외, 센서 응답 시간 최대 15초 별도) | EXP-4 |
| 위치 추적 가능성 | 웨어러블 노드의 2D 위치가 대시보드에 실시간으로 표시 | EXP-2, EXP-3 |
| 시각화 가능성 | 3D 디지털 트윈 모형 위에 센서 위치와 위험도가 색상으로 표시 | EXP-5 |
| 이력 조회 가능성 | 특정 시간 범위의 시계열 데이터를 차트로 조회할 수 있다 | — |
| 산소 모니터링 | 웨어러블 O₂ 센서가 작업자 주변 산소 농도를 측정하고 임계값 경보 발생 | EXP-1 |

### 1.4 MVP 범위

**포함:**

- Full-Spec 센서 노드 4개 (CO₂·CO·H₂S·가스저항·온습도 + UWB Anchor)
- 웨어러블 노드 1개 (O₂·낙상 감지·UWB Tag·진동 알림)
- MQTT 기반 실시간 데이터 수집
- 임계값 기반 3단계 위험도 경보 (Hysteresis 적용)
- 웹 대시보드 (실시간 수치·차트·경보 로그)
- 3D 디지털 트윈 시각화 (동기화된 객체 모델, 위치·위험도·IDW 히트맵)
- 시계열 데이터 저장 및 조회
- 안전한 데이터 주입 기반 시연 시나리오

**제외 (OUT OF SCOPE):**

- MLX90640 열화상 카메라 (고정형 독립 노드는 MVP 2차로 연기, ESP32 추가 필요)
- 3D 위치 추적 (측위는 2D 고정)
- TDoA 방식 UWB 측위 (DS-TWR만 사용)
- AIS·외부 기상 API 연동
- 다중 현장 동시 모니터링
- 사용자 권한 관리 고도화
- 모바일 앱
- 공식 산업안전보건 보고서 생성
- 자동 대피 유도 시스템 제어
- LSTM 가스 농도 예측 (Research Track / MAY)

## 3. 하드웨어 구성

> 상세한 하드웨어 설계는 `03_HARDWARE_DESIGN.md`, 구매 부품 목록은 `docs/BOM.md`를 참조한다.

### 3.1 노드 구성 요약

| 노드 | 수량 | 메인보드 | 측정 항목 | UWB 역할 | 통신 |
|------|------|----------|-----------|----------|------|
| Full-Spec 센서 노드 | 4 | ESP32 DevKitC V4 | CO₂·CO·H₂S·가스저항·온습도 | Anchor | WiFi → MQTT |
| 웨어러블 노드 | 1 | ESP32 DevKitC V4 | O₂·낙상(IMU) | Tag | WiFi → MQTT |

> 센서 노드 4개는 모두 동일한 Full-Spec 구성이다. 메인/서브 구분은 존재하지 않는다. (ADR-001 참조)

### 3.2 센서별 측정 항목

| 센서 | 측정 대상 | 통신 방식 | 전원 | 출력 필드 |
|------|-----------|-----------|------|-----------|
| MH-Z19B | CO₂ (ppm) | UART | 5V | co2_ppm |
| BME680 | 온도·습도·기압·가스저항(Ω)·IAQ | I2C | 3.3V | temperature_c, humidity_pct, pressure_hpa, gas_resistance_ohm, iaq_index, iaq_accuracy |
| MQ-7 | CO (아날로그) | ADS1115 → I2C | 5V | raw_adc, voltage_v, rs_ohm, rs_r0_ratio, estimated_ppm(null if uncalibrated), calibration_status |
| MQ-136 | H₂S (아날로그) | ADS1115 → I2C | 5V | raw_adc, voltage_v, rs_ohm, rs_r0_ratio, estimated_ppm(null), calibration_status |
| MQ-2 | 가연성 가스 (아날로그) | ADS1115 → I2C | 5V | raw_adc, voltage_v, rs_ohm, rs_r0_ratio, estimated_concentration(null), calibration_status |
| SEN0322 | O₂ (%) | I2C (Graupner) | 3.3V | o2_pct |
| MPU-6050 | 6축 가속도·자이로 | I2C | 3.3V | 가속도 XYZ, 자이로 XYZ, 낙상 감지 여부 |
| DWM1000 BU01 | UWB 거리 측정 | SPI | 3.3V | 거리 (DS-TWR), 위치 (x, y) |

> BME680은 VOC ppm으로 표현하지 않는다. Bosch 공식 사양상 가스 저항(Ω)과 BSEC IAQ 지수를 사용한다. (ADR-001, `08_SAFETY_AND_LIMITATIONS.md` 참조)
>
> MQ 센서는 교정 전까지 ppm 또는 LEL% 대신 raw_adc, voltage, Rs/R0를 표시한다.

### 3.3 UWB 위치 측위 구성

| 항목 | 내용 |
|------|------|
| 앵커(Anchor) | 센서 노드 4개 — 고정 위치에 배치 |
| 태그(Tag) | 웨어러블 노드 1개 — 작업자 착용 |
| 측위 방식 | DS-TWR (Double-Sided Two-Way Ranging) |
| 측위 차원 | 2D (x, y) |
| 앵커 수 | 4개 |
| 측위 정밀도 목표 | ±30cm 이내 (LOS 기준, 실험 목표값이며 보장값이 아님) |

> TDoA는 MVP에서 제외한다. DS-TWR만 사용한다. (ADR-002 참조)
>
> ±30cm는 실험 목표값이다. Qorvo 사양상 DW1000의 이상적 정밀도는 10cm 수준이나, 실제 성능은 안테나 지연 보정과 NLOS 조건에 크게 좌우된다. `07_EXPERIMENT_PLAN.md` Experiment 2에서 검증한다.

### 3.4 데이터 수집 및 발행 주기

모든 문서에서 동일한 주기를 사용한다.

| 데이터 | 센서 샘플링 | MQTT 발행 |
|--------|-------------|-----------|
| CO₂ (MH-Z19B) | 1초 | 1초 |
| MQ 계열 (MQ-7, MQ-136, MQ-2) 원시값 | 1초 | 1초 (또는 2초 평균) |
| 온습도 (BME680) | 1초 | 5초 |
| O₂ (SEN0322) | 1초 읽기 | 5초 |
| IMU (MPU-6050) | 50~100Hz | 특징값 10Hz |
| UWB 위치 | 5~10Hz (가능한 범위) | 5~10Hz |
| 노드 상태 (배터리, RSSI) | 지속 측정 | 10초 |

> SEN0322 O₂ 센서의 공식 응답 시간은 최대 15초 수준이다. O₂ 변화에 대해 "3초 이내 탐지"를 요구하지 않는다. 전체 경보 3초 목표와 O₂ 센서 자체 응답 시간을 별도로 관리한다.

## 4. 기능 요구사항

### 기능 1: 실시간 환경 모니터링

#### FR-101 데이터 수집

- **MUST**: 모든 센서 노드(4개)는 CO₂·CO·H₂S·가스저항·온도·습도를 측정한다. (Full-Spec)
- **MUST**: 센서 데이터는 위 3.4의 주기에 따라 MQTT 브로커에 전송된다.
- **MUST**: 모든 측정값에는 노드 ID, 시퀀스 번호, UTC 타임스탬프(sampled_at, published_at), 품질 정보가 포함된다.
- **MUST**: 웨어러블 노드는 O₂ 농도와 IMU 데이터를 측정하고 전송한다.
- **SHOULD**: 전송 실패 시 로컬 버퍼에 최대 100건을 저장하고 재전송한다.

> 실험 연결: EXP-1 (센서 통신 안정성)

#### FR-102 MQTT 토픽 구조

> 상세한 페이로드 스키마는 `04_DATA_CONTRACT.md` 및 `schemas/` 디렉토리의 JSON Schema를 참조한다.

```
sensors/{node_id}/gas       → CO₂, CO, H₂S, MQ-2, BME680 가스저항/IAQ
sensors/{node_id}/env       → 온도, 습도, 기압
sensors/{node_id}/status    → 배터리, WiFi RSSI, 업타임, 센서 상태
wearable/{node_id}/location → UWB x, y, z(fixed=0.0), 품질, 앵커 수
wearable/{node_id}/imu      → 가속도, 자이로, 낙상 감지 여부
wearable/{node_id}/vital    → O₂ 농도
alerts/events/{node_id}            → 경보 발령 이벤트 (서버 발행, Retain 없음)
alerts/state/{node_id}/{alert_key}    → 경보 상태 (서버 발행, Retain, alert_key별 유지)
```

#### FR-103 데이터 저장

- **MUST**: 서버는 수신 데이터를 TimescaleDB에 저장한다.
- **MUST**: 원시 데이터(1초)와 1분 평균값을 모두 저장한다.
- **MUST**: 경보 이벤트 로그는 영구 보관한다.
- **SHOULD**: 원시 데이터는 30일 보관 후 삭제한다.
- **MUST**: 메시지 중복은 message_id 기준으로 방지한다.

### 기능 2: 위험도 판정 및 경보

> 상세한 경보 규칙, Hysteresis, 알고리즘 단계는 `06_ALERT_RULES.md`를 참조한다.

#### FR-201 가스 농도 임계값

| 항목 | 정상 | Level 1 (주의) | Level 2 (경고) | Level 3 (위험) |
|------|------|----------------|----------------|----------------|
| CO₂ | < 1,000 ppm | 1,000–2,000 ppm | 2,000–5,000 ppm | ≥ 5,000 ppm |
| CO | < 25 ppm | 25–50 ppm | 50–200 ppm | ≥ 200 ppm |
| H₂S | < 1 ppm | 1–5 ppm | 5–10 ppm | ≥ 10 ppm |
| 온도 | < 35°C | 35–38°C | 38–40°C | ≥ 40°C |

> MQ-2와 BME680은 교정 전까지 임계값 기반 경보에서 제외한다. raw 값 모니터링만 수행한다.
>
> O₂ 임계값은 SEN0322 응답 시간(최대 15초)을 고려하여 단독 임계값 경보로만 운용한다.

| 항목 | 정상 | Level 1 | Level 2 | Level 3 |
|------|------|---------|---------|---------|
| O₂ (저농도) | 19.5–23.5% | 18.0–19.5% | 16.0–18.0% | < 16.0% |
| O₂ (고농도) | 19.5–23.5% | > 23.5% | > 25.0% | > 28.0% |

> O₂는 양방향 경보이다. o2_low(저농도)와 o2_high(고농도)를 별도 alert_key로 관리한다. 상세한 Hysteresis 규칙은 `06_ALERT_RULES.md` 섹션 4.2를 참조한다.

- **MUST**: 임계값은 코드에 하드코딩하지 않는다. DB 또는 설정 파일에서 관리하며 관리자가 수정할 수 있어야 한다.
- **MUST**: Hysteresis를 적용한다. 경보 발생은 시간 기반(enter_for_ms) 지속 조건, 해제는 시간 기반(exit_for_ms) 지속 조건으로 판정한다. 경보 해제 시 한 단계씩만 하향한다(de-escalation).

> 실험 연결: EXP-4 (End-to-End 경보 지연)

#### FR-202 낙상 감지

- **MUST**: MPU-6050 가속도 합성벡터가 2.5g 이상 순간 급변 후 1초 이상 정적 상태 지속 시 낙상으로 판정한다.
- **MUST**: 낙상 판정 시 즉시 Level 3 경보를 발령한다.
- **MAY**: 작업자가 오감지를 취소할 수 있는 버튼을 제공한다.
- **MAY**: 충분한 학습 데이터 확보 후 SVM/Random Forest 분류 모델로 오탐 감소 (Research Track)

#### FR-203 경보 발령 규칙

- **MUST**: 임계값 초과 감지 후 3초 이내 경보가 발령된다. (P95 기준)
- **MUST**: Level 1 이상 경보 시 웨어러블 진동 모터가 작동한다.
- **MUST**: Level 3 경보 시 웹 대시보드에 팝업 알림 및 사이렌 알림음이 발생한다.
- **MUST**: 경보 발령 시 노드 위치, 측정값, 시각이 이벤트 로그에 기록된다.
- **MUST**: 임계값 이하로 복귀 시 경보 해제 이벤트가 기록된다 (Hysteresis 적용).
- **MUST**: IDW 공간 보간 추정값은 경보 판정에 사용하지 않는다. 실제 센서 측정값으로만 판정한다. (ADR-005)

#### FR-204 경보 진동 패턴

| 위험 등급 | 진동 패턴 |
|-----------|-----------|
| Level 1 (주의) | 0.5초 진동 × 2회 |
| Level 2 (경고) | 1초 진동 × 3회, 반복 |
| Level 3 (위험) | 연속 진동, 중단 없음 |

#### FR-205 경보 알고리즘 단계

| 단계 | 상태 | 설명 |
|------|------|------|
| 1단계 | MUST | 실측 임계값 + 변화율 + 일정 시간 지속 조건 + Hysteresis |
| 2단계 | SHOULD | 이동 평균, 선형 회귀 또는 EWMA로 상승 추세 표시 |
| 3단계 | MAY (Research Track) | 충분한 실험 데이터 확보 후 LSTM 평가 |

> 복합 위험 점수(가중치 조합)는 실험 검증 전까지 참고 지표로만 사용한다.

---

### 기능 3: 작업자 위치 추적

#### FR-301 위치 측정 및 표시

- **MUST**: 웨어러블 노드의 2D 위치(x, y)가 대시보드에 실시간으로 표시된다.
- **MUST**: 위치 업데이트 주기는 5~10Hz이다.
- **MUST**: 측위 방식은 DS-TWR 기반 2D 위치 계산이다.
- **MUST**: 위치 데이터에는 품질 점수(quality), 앵커 수(anchor_count), 필터 적용 여부(is_filtered)가 포함된다.
- **MUST**: z 좌표는 항상 0.0으로 고정하며, 3D 렌더링용 렌더링 좌표이다.
- **SHOULD**: 작업자 이동 경로가 일정 시간 동안 궤적으로 표시된다.
- **SHOULD**: 작업자가 위험 구역(Level 2 이상 경보 발령 노드 반경 0.5m)에 진입 시 추가 경보를 발령한다.
- **OUT OF SCOPE**: 3D 위치 추적

> 실험 연결: EXP-2 (UWB 정적 위치 정확도), EXP-3 (동적 위치 추적)

#### FR-302 위치 필터링

- **MUST**: 이상치 제거 후 2D Least Squares 위치 계산을 수행한다.
- **SHOULD**: EMA(Exponential Moving Average) 필터를 적용한다.
- **MAY**: Kalman Filter를 순차적으로 적용한다 (EMA 안정화 후).

### 기능 4: 웹 대시보드

> 상세한 화면 구조, 컴포넌트 배치, 인터랙션 흐름은 `10_UI_FLOW.md`를 참조한다.

#### FR-401 실시간 모니터링 화면

- **MUST**: 전체 노드의 현재 측정값이 카드 형태로 표시된다.
- **MUST**: 위험 등급에 따라 카드 색상이 변경된다 (정상: 초록, 주의: 노랑, 경고: 주황, 위험: 빨강).
- **MUST**: 경보 발령 중인 노드는 강조 표시된다.
- **MUST**: 센서 교정 상태(calibration_status)가 표시된다.
- **SHOULD**: 각 노드별 최근 1시간 추세 미니 차트가 표시된다.

#### FR-402 시계열 차트 화면

- **MUST**: 노드, 항목, 시간 범위를 선택하여 시계열 차트를 조회할 수 있다.
- **MUST**: 차트에 임계값 기준선이 표시된다.
- **SHOULD**: CSV 내보내기가 가능하다.

#### FR-403 이벤트 로그 화면

- **MUST**: 경보 발령·해제 이력이 시간 역순으로 표시된다.
- **MUST**: 이벤트별 노드 ID, 측정값, 등급, 발령 시각이 표시된다.
- **SHOULD**: 날짜, 등급, 노드 기준 필터가 제공된다.

### 기능 5: 3D 디지털 트윈 시각화

> 상세한 디지털 트윈 사양은 `05_DIGITAL_TWIN_SPEC.md`를, 3D 화면의 컴포넌트 배치 및 인터랙션 흐름은 `10_UI_FLOW.md`를 참조한다.

#### FR-501 디지털 트윈 기본 기능

- **MUST**: 시뮬레이션 모형(밀폐공간 축소 재현)을 기반으로 한 3D 공간 모델이 표시된다.
- **MUST**: 각 센서 노드 위치가 3D 공간 위에 마커로 표시된다.
- **MUST**: 마커 색상은 위험도 등급에 따라 변경된다.
- **MUST**: 웨어러블 노드(작업자)의 위치가 3D 공간 위에 실시간으로 이동한다.
- **MUST**: Physical ID와 3D Object ID가 매핑된다.
- **SHOULD**: 특정 노드 마커 클릭 시 현재 측정값 팝업이 표시된다.
- **MUST**: IDW 히트맵은 시각화 전용이며, 화면에 "Estimated concentration surface based on IDW interpolation" 레이블이 표시된다.

#### FR-502 디지털 트윈 동기화

- **MUST**: Twin 객체(Space, SensorNode, Wearable, HazardZone, Alert)의 상태가 실시간 데이터와 동기화된다.
- **MUST**: WebSocket 재연결 후 최신 상태 Snapshot으로 복구된다.
- **SHOULD**: Timeline Replay 기능을 제공한다 (특정 시간대 재생).
- **SHOULD**: 데이터 품질 상태(교정 여부, 센서 상태)가 3D 화면에 표시된다.

> 실험 연결: EXP-5 (IDW 공간 보간 정확도)

### 5.1 성능

| 항목 | 목표 | 측정 기준 |

| UWB 위치 업데이트 주기 | 5~10Hz | — |

### 5.2 가용성

- **SHOULD**: WiFi 재연결 실패 시 센서 노드는 로컬 LED로 연결 상태를 표시한다.
- **SHOULD**: MQTT 브로커 재시작 후 노드가 자동으로 재접속한다.
- **MUST**: 노드 오프라인 판정은 Last Will and Testament(LWT) 메시지 또는 30초 이상 데이터 수신 없음으로 수행한다.
- **MAY**: 서버 장애 시 최근 경보 이력이 로컬 스토리지에 보존된다.

> 실험 연결: EXP-6 (장애 및 복구)

### 5.3 보안

- **SHOULD**: MQTT 브로커는 인증(username/password) 또는 TLS를 적용한다.
- **SHOULD**: 대시보드 접근은 로그인 인증이 필요하다.
- **MAY**: 노드별 인증 토큰을 발급한다.

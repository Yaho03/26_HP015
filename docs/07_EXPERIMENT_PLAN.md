## 1. 개요

본 문서는 시스템의 성능을 객관적으로 측정하고 합격/불합격을 판정하기 위한 실험 계획을 정의한다. 모든 실험은 재현 가능해야 하며, Ground Truth 측정 방법과 통계적 기준을 명시한다.

### 합격 기준 원칙

- 합격 기준은 평균이 아닌 **P95 (95번째 백분위수)** 기준으로 작성한다
- 모든 실험은 최소 3회 반복한다
- 원본 데이터는 CSV 형식으로 저장한다

### UWB 리스크 관리 (Go/No-Go 결정점)

UWB DS-TWR 측위는 본 프로젝트에서 **가장 높은 일정 리스크**를 가진다. 안테나 지연 보정, NLOS 대응, 펌웨어 구현에 4~6주가 소요될 수 있다.

| 결정점 | 시점 | Go 조건 | No-Go 조치 |
|---------|------|---------|-----------|
| Week 4 | DWM1000 SPI 통신 및 단일 앵커 거리 측정 성공 | 통신 불가 시 → ESP32 UWB 라이브러리 교체 또는 하드웨어 점검 |
| Week 6 | 4 앵커 DS-TWR + 2D 위치 계산 동작 | **±50cm 이내 달성 시 Go**. 달성 못함 → 사전 녹화된 위치 데이터 재생으로 데모 대체 (실시간 UWB 포기) |

> No-Go 시에도 3D 디지털 트윈 시각화, 가스/온습도 경보, 낙상 감지는 정상 동작한다. UWB 위치 추적만 시뮬레이션 데이터로 대체한다.

## 2. 타임스탬프 정의

모든 실험에서 다음 5단계 타임스탬프를 기록한다.

| 타임스탬프 | 측정 주체 | 설명 |
|------------|-----------|------|
| `sampled_at` | 센서 노드 | 센서에서 값을 읽은 시각 |
| `published_at` | 센서 노드 | ESP32가 MQTT publish 호출 시각 |
| `backend_received_at` | 백엔드 서버 | 백엔드 서버가 MQTT 메시지를 수신한 시각 (MQTT broker가 자동으로 추가하지 않음, 백엔드에서 기록) |
| `stored_at` | 백엔드 서버 | DB 저장 완료 시각 |
| `rendered_at` | 대시보드 | 프론트엔드 화면 렌더링 완료 시각 |

> 이 타임스탬프들을 통해 센서 지연, 네트워크 지연, 백엔드 처리 지연, 렌더링 지연을 구분할 수 있다.

## EXP-1: 센서 통신 안정성

### 목적

센서 노드 4개가 장시간 안정적으로 데이터를 전송하는지 검증한다.

### 조건

| 항목 | 값 |
|------|-----|
| 실행 시간 | 최소 2시간 연속 |
| 센서 노드 | 4개 동시 |
| 발행 주기 (per-topic, per-node) | gas: 1초 주기, env: 5초 주기, status: 10초 주기 |
| 총 예상 메시지 (per node) | gas: 7,200건 / 노드, env: 1,440건 / 노드, status: 720건 / 노드, 합계: 9,360건 / 노드 |
| 총 예상 메시지 (4 sensor nodes) | 37,440건 |
| 웨어러블 노드 예상 메시지 | location (5Hz): 36,000건, vital (5s): 1,440건, imu (10Hz): 72,000건 |

### 측정 항목

| 항목 | 설명 |
|------|------|
| 수신율 | 수신 메시지 수 / 예상 메시지 수 (topic별 및 노드별로 집계) |
| 중복률 | 중복 message_id 수 / 전체 수신 수 |
| 순서 역전 | sequence 감소 횟수 |
| 재접속 시간 (P95) | MQTT 연결 끊김 후 재연결까지 시간 (P95) |

### 합격 기준

| 항목 | 기준 |
|------|------|
| 수신율 | >= 99% |

> QoS 1 토픽(gas, env, status, location, vital)의 수신율은 >= 99%를 적용한다. QoS 0 토픽(IMU, 10Hz)은 일부 손실이 허용되므로 수신율 목표에서 제외한다.
| P95 메시지 지연 (sampled_at -> stored_at) | <= 3초 |
| 중복률 | <= 0.1% |
| 재접속 시간 (P95) | <= 10초 |

### 데이터 저장

각 메시지의 5단계 타임스탬프를 CSV로 저장한다.

```
message_id,node_id,sequence,sampled_at,published_at,backend_received_at,stored_at,rendered_at
```

## EXP-2: UWB 정적 위치 정확도

### 목적

UWB DS-TWR 측위 시스템의 정적 위치 정확도를 측정한다.

### Ground Truth 측정

| 항목 | 값 |
|------|-----|
| 그리드 | 5 x 5 grid |
| 간격 | 0.5m |
| 총 측정 지점 | 25개 |
| 지점당 측정 시간 | 30초 |
| 반복 횟수 | 각 조건 3회 |

### 측정 조건

| 조건 | 설명 |
|------|------|
| LOS (Line of Sight) | 앵커와 태그 사이 장애물 없음 |
| 금속 장애물 1개 | 앵커-태그 경로에 금속판 1개 |
| 신체 가림 | 작업자 신체로 Tag 차폐 |
| 모서리 | 모형 모서리 근처 |
| 중앙 | 모형 정중앙 |
| 출입구 | 출입구 근처 |

### 평가 지표

| 지표 | 설명 |
|------|------|
| Median Error | 오차의 중앙값 |
| MAE | Mean Absolute Error |
| RMSE | Root Mean Square Error |
| P95 Error | 95번째 백분위수 오차 |
| 최대 오차 | 측정된 최대 위치 오차 |
| 위치 업데이트율 | 위치 메시지 수신 빈도 |
| 데이터 손실률 | 예상 위치 메시지 대비 수신 비율 |

### 합격 기준

| 조건 | Median | P95 |
|------|--------|-----|
| LOS | <= 30cm | <= 60cm |
| NLOS | <= 60cm | <= 120cm |

> Qorvo는 DW1000의 이상적 측위 정밀도를 10cm 수준으로 안내한다. 그러나 실제 성능은 안테나 지연 보정과 NLOS 조건에 크게 좌우된다. 본 합격 기준은 실험 목표값이며 보장값이 아니다.

## EXP-3: 동적 위치 추적

### 목적

작업자 이동 시 UWB 위치 추적의 정확도와 지연을 측정한다.

### 측정 경로

| 경로 | 설명 |
|------|------|
| A | 직선 이동 |
| B | 사각형 경로 |
| C | 장애물 우회 |
| D | 위험 구역 진입 및 이탈 |

### Ground Truth

- 모형 바닥에 0.5m 간격 눈금 테이프 부착
- 작업자가 정해진 경로를 일정한 속도(약 0.5m/s)로 이동
- 각 경로를 3회 반복 측정

### 측정 통계

본 절에서는 위치 추적의 동적 성능(위치 추적 정확도)과 위치 품질에 대한 통계(quality metrics)를 분리하여 기록한다.

- 위치 추적 정확도 지표:
  - 위치 갱신 빈도: Hz 단위 위치 업데이트 빈도
  - 실제 경로 대비 평균 오차: 측정 경로와 Ground Truth 경로 간 평균 거리
  - 순간 점프 횟수: 이전 위치 대비 1m 이상 급변 횟수
  - 최대 정지 시간: 위치 갱신이 없었던 최대 연속 시간
  - 화면 반영 지연: 위치 측정 시각부터 화면 표시까지 시간
  - 위험 구역 진입 감지 지연: 실제 진입 시각부터 경보 발령까지 시간

- 위치 품질 지표:
  - quality_score 통계: 평균, P5 (하위 5%)
  - anchor_count 분포: 각측정 시점에서 사용된 앵커 수의 분포
  - is_filtered 비율: 필터링(거리 이상치/점프 필터 등)에 의해 폐기된 측정의 비율

### 평가 지표 (요약)

| 지표 | 설명 |
|------|------|
| 위치 갱신 빈도 | Hz 단위 위치 업데이트 빈도 |
| 평균 경로 오차 (P95) | 측정 경로와 Ground Truth 간 거리의 P95 |
| 순간 점프 횟수 | 1m 이상 급변 횟수 (정규화: 회/분) |
| 화면 반영 지연 (P95) | 측정->화면 표시 지연의 P95 |
| 위험 구역 진입 감지 지연 (P95) | 실제 진입->경보 발령 지연 P95 |
| quality_score 평균, P5 | 위치 품질 점수의 평균 및 하위 5% |
| anchor_count 분포 | 앵커 수 분포 (히스토그램) |
| is_filtered 비율 | 필터링된 측정 비율 |

### 합격 기준

| 항목 | 기준 |
|------|------|
| 위치 갱신 빈도 | >= 5Hz |
| 평균 경로 오차 (P95) | <= 50cm |
| 순간 점프 횟수 | <= 1회/분 |
| 화면 반영 지연 (P95) | <= 1초 |
| 위험 구역 진입 감지 지연 (P95) | <= 2초 |

## EXP-4: End-to-End 경보 지연

### 목적

센서값 생성부터 웨어러블 진동 및 대시보드 표시까지의 전체 경보 지연을 측정한다.

### 측정 시점

| 시점 | 설명 |
|------|------|
| T0 | 센서값 생성 (sampled_at) |
| T1 | MQTT publish (published_at) |
| T2 | 백엔드 수신 (backend_received_at) |
| T3 | DB 저장 완료 (stored_at) |
| T4 | 위험 판정 완료 (judged_at) |
| T5 | Alert publish (서버가 alerts 토픽 발행) |
| T6 | 웨어러블 진동 시작 (진동 모터 구동 확인) |
| T7 | Web UI 경보 표시 (rendered_at) |

### 지연 분해

| 지연 구간 | 계산 |
|-----------|------|
| Wearable alert latency | T6 - T0 |
| Dashboard alert latency | T7 - T0 |
| Backend processing | T4 - T2 |
| Network latency | T2 - T1 |

### 측정 방법

1. 데이터 주입: 실험용 페이로드에서 실제 센서의 node_id (예: "sensor-01")를 사용하되, envelope에 `source_mode: "simulation"` 필드를 추가하여 시뮬레이션 소스로 표기한다. (예: { node_id: "sensor-01", source_mode: "simulation", ... })
2. 각 단계별 타임스탬프를 기록한다.
3. T6 (진동 시작) 측정: 진동 모터 구동 시작 시점을 고속 카메라(최소 120fps)로 촬영하여 프레임 기준으로 시작 시점을 결정한다. 진동 센서(예: 가속도계)를 보조 측정으로 사용하되, 고속 카메라를 Ground Truth로 삼는다.
4. T7 (UI 표시) 측정: 프론트엔드 콘솔의 타임스탬프를 기록한다.

### 합격 기준

> P95 3초 목표는 **시스템 전송 지연**(T4→T6)에만 적용한다. `enter_for_ms`(탐지 지연, T0→T4)는 오탐 방지용 의도적 지연이므로 별도 측정한다. 상세는 `06_ALERT_RULES.md` 섹션 6.1 참조.

| 항목 | 기준 | 측정 구간 |
|------|------|-----------|
| P95 시스템 전송 지연 | <= 3초 | T4(판정완료) → T6(진동) |
| P95 총 경보 지연 | 참고용 | T0(sampled_at) → T6(진동) |
| P95 Dashboard 전송 지연 | <= 3초 | T4 → T7(UI 렌더) |
| Backend processing (중앙값) | <= 500ms | T2 → T4 |

> O₂ 경보는 센서 응답 시간(최대 15초)으로 인해 3초 목표에서 제외한다. 단, T4→T6(시스템 전송)은 측정한다.

## EXP-5A: IDW 보간 정확도 (합성 데이터)

### 목적

합성 가스 필드(소프트웨어로 생성한 CO₂ 농도 그라디언트)를 센서 노드에 주입한 것으로 가정하고, IDW(Inverse Distance Weighting) 보간 수학적 정확성을 검증한다. 알고리즘 자체의 구현 오류를 찾아내기 위한 실험이다.

### 방법

- 합성 데이터셋 생성: 노드 위치와 알려진 CO₂ 농도 분포(그라디언트 및 랜덤 노이즈 포함)를 소프트웨어로 생성한다.
- Leave-One-Out: 4개 센서 중 하나를 제거하고 나머지 센서로 제거된 노드의 값을 예측한다. 모든 조합에 대해 수행.
- 보간 파라미터는 실사용 값(가중치 지수 등)을 사용하며, 파라미터 값 별 성능도 기록한다.

### 평가 지표

| 지표 | 설명 |
|------|------|
| MAE | Mean Absolute Error |
| RMSE | Root Mean Square Error |
| 최대 오차 | 단일 예측의 최대 오차 |

### 합격 기준 및 목적

- EXP-5A의 목적은 IDW 수치 알고리즘이 수학적으로 올바르게 구현되었는지 검증하는 것임.
- 합격 기준: 합성 데이터에서 MAE와 RMSE가 사전 정의된 임계값(실험 전 정의) 이하이고, 최대 오차가 허용 범위 이내일 것. (자세한 임계값은 실험 시 정의)

## EXP-5B: IDW 보간 일관성 (실제 센서)

### 목적

실제 센서에서 취득한 CO₂ 데이터를 사용하여 IDW 보간의 일관성을 검증한다. 실제 환경에서 센서가 상대적으로 균일한 구역을 대상으로 2시간 이상 데이터를 수집하여 보간의 일관성을 평가한다.

### 방법

- 실제 센서 데이터 수집: 4개 센서에서 2시간 이상 연속 데이터 수집
- Leave-One-Out: 각 센서를 검증용으로 제외하고 보간 수행
- 보간 결과와 실제 값을 비교하여 통계 산출

### 평가 지표

| 지표 | 설명 |
|------|------|
| MAE | Mean Absolute Error |
| 위험 등급 일치율 | 예측 등급과 실제 등급(안전/주의/위험)이 일치하는 비율 |

### 합격 기준 및 목적

- EXP-5B의 목적은 실세계 데이터에서 보간이 일관되게 동작하는지 확인하는 것임.
- 합격 기준: MAE가 사전 정의된 임계값 이하이고, 위험 등급 일치율 >= 80%.
- EXP-5A는 알고리즘 검증을, EXP-5B는 실제 환경에서의 일관성 검증을 각각 담당한다.

## EXP-6: 장애 및 복구

### 목적

시스템 구성 요소의 장애 상황에서 자동 복구 능력을 검증한다.

### 장애 시나리오

## EXP-7: 작업자 누적 노출량 (FR-701~708)

### 목적

적산 결과가 **해석적 계산값과 일치하는지**, 그리고 데이터가 끊기거나 프로세스가 죽었을 때
누적값이 **폭주하거나 조용히 사라지지 않는지** 확인한다.

이 실험의 핵심은 정확도보다 **실패 모드**다. 노출량은 한 번 틀리면 화면에서 틀린 줄 알 수
없다 — 순간 농도와 달리 눈으로 대조할 대상이 없다.

### 전제

- 적산 산수는 `exposure_accumulator.py`에 **순수 함수**로 분리돼 있다. DB·시계·네트워크를
  타지 않으므로 해석적 정답과 직접 비교할 수 있다.
- 사다리꼴 적분은 **선형 구간에서 정확**하다. 따라서 상수·선형 램프 프로파일에서는
  오차 ≤ 2%가 아니라 **오차 0**이 나와야 한다. 2% 기준은 실측 프로파일용 여유다.
- 기준값(`exposure_limits`)이 시드되지 않은 metric은 `dose_fraction`이 `null`이다.
  **이 상태에서 0%가 나오면 그 자체가 불합격이다.**

### 방법 및 합격 기준

| Test ID | 방법 | 합격 기준 | 현재 상태 |
|---------|------|-----------|-----------|
| EXP-7 | 상수·선형 램프 농도 프로파일을 주입해 적산 정확도 검증 | 해석적 계산값 대비 오차 ≤ 2% | ✅ 자동화 (`test_exposure_accumulator.py`) — 상수·램프 모두 **정확히 일치**, 샘플링 간격을 바꿔도 결과 불변 |
| EXP-7.1 | 적산 중 백엔드 강제 재시작 | 복구 후 dose 연속성 유지, 손실 ≤ `flush_interval_s` 분량 | ✅ 자동화 (`integration/test_exposure_recovery.py`) — 아래 참조 |
| EXP-7.2 | 노드 오프라인 5분 구간 주입 | `data_gap_s` 정확히 기록, dose 폭주 없음 | ✅ 자동화 — `gap_max_s` 초과분 미적산, `accumulated_s + data_gap_s = elapsed_s` 항등식 고정 |
| EXP-7.3 | 기준값 미시드 상태로 전 경로 확인 | `dose_fraction`이 `null`, 경보 미발령, 화면이 "기준값 미검증" 표기 | ✅ 자동화 (`test_exposure_service.py`, `exposure.test.ts`) |
| EXP-7.4 | 작업자 측위 상실 구간 주입 | 적산 **중단**(추정 금지), `data_gap_s` 증가 | ✅ 자동화 (`test_no_position_stops_accumulation_instead_of_guessing`) |

### EXP-7.1 측정 방법 — 재시작 연속성

`backend/tests/integration/test_exposure_recovery.py`가 실제 TimescaleDB에 붙어
**적산 → flush → 메모리 전멸 → `_recover()` → 이어서 적산**을 한 줄로 꿴다.
`_windows`를 비우는 것이 핵심이다 — 남겨두면 복구가 아니라 기존 상태를 다시 쓰는 것이라
아무것도 검증되지 않는다.

| 확인 항목 | 결과 |
|---|---|
| flush된 누적이 재기동 후 남고 이어서 쌓인다 | ✅ |
| `exposure_id`가 보존된다 (윈도우가 새로 열리지 않는다) | ✅ 갈라지면 교대 로그가 두 조각이 된다 |
| 손실이 **정확히** 마지막 flush 이후 증분이다 | ✅ 그 이상도, 이하도 아니다 |
| 다운타임이 `data_gap_s`로 가고 dose가 폭주하지 않는다 | ✅ 880초 공백에서 `gap_max_s` 초과분 820초가 공백으로 기록 |
| 재기동이 활성 윈도우를 중복 생성하지 않는다 | ✅ |
| 배정이 해제된 채 재기동해도 누적과 **이름**이 남는다 | ✅ |

**검증되지 않는 것**: 실제 프로세스를 죽였다 살리지는 않는다. asyncio 루프·컨테이너
재기동·커넥션 풀 재생성은 범위 밖이다. 검증되는 것은 "영속화된 상태만으로 적산을
재개할 수 있는가"다. 컨테이너 단위 확인이 필요하면 위 표의 항목을 그대로
`GET /api/exposure/current`로 재확인하면 된다.

### EXP-7.1 이 찾아낸 결함 (다운타임 중 교대)

이 검증을 만들면서 **실제 버그가 드러났다.** 기록해 둔다.

`_windows`는 `(node_id, metric)` 키인데 `uq_exposure_state_active`는 **worker_id를 포함한**
키다. 그래서 백엔드가 꺼진 사이 웨어러블이 다른 작업자에게 넘어가면 A와 B의 윈도우가
DB에 동시에 열려 있을 수 있다.

이전 구현은 두 곳에서 이를 놓쳤다.

1. `_reconcile()`이 키가 이미 있으면 **`worker_name`만 바꿔 달았다.** worker_id는 A인 채로
   이름만 B가 되어, B의 노출이 A의 `exposure_id`에 쌓이고 교대 로그가
   **`worker_id=A` / `worker_name=B`** 라는 자기모순인 행으로 확정된다.
2. `_recover()`가 윈도우 이름을 **현재 배정**에서 가져왔다. A의 윈도우에 B의 이름이 붙는다.

`exposure_shift_log.worker_name`은 workers FK 없이 비정규화된 컬럼이다 — 작업자 행이
지워져도 그 교대에 누가 있었는지가 남아야 하기 때문이다. 거기에 다른 사람 이름이
들어가면 그 목적이 무너진다.

수정: 착용자가 바뀌면 이전 윈도우를 **확정하고 새로 연다.** 이름은 현재 배정이 아니라
윈도우가 가리키는 `worker_id`로 조회한다. 활성 윈도우가 둘 이상이면 현재 배정된 쪽을
고르고, 나머지가 DB에 열린 채 남는다는 사실을 경고 로그로 남긴다 (조용히 고르지 않는다).

### 알려진 한계 (결과 보고 시 함께 적을 것)

1. **작업자 위치 농도는 최근접 고정 노드 실측값 대입이다** (ADR-008). 노드 사이 중간
   위치의 오차는 정량화되지 않았다.
2. **CO·H₂S는 MQ 센서 미교정으로 산출 불가**다. MVP 기간 내내 `unavailable`이며,
   따라서 EXP-7의 실측 검증은 사실상 CO₂ 단독이다.
3. 개인 호흡영역 측정이 아니므로 **법정 작업환경측정을 대체하지 않는다.**
4. **흡수·배출 생리 모델이 없다.** 산출값은 체내 축적량이 아니라 환경 노출량이다.
5. 호흡보호구 착용을 반영하지 않는다 → 실제보다 **과대평가** 방향.
6. **노출 기준값의 원문 대조 서명이 아직 비어 있다** (`EXPOSURE_LIMITS_VERIFICATION.md` §2).
   서명 전에는 소진율(%)을 안전 판단 근거로 제시해서는 안 된다.

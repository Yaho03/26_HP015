## 1. 사전 준비

### 1.1 안전 점검 — 실험 시작 전 필수 확인

| 항목 | 기준 |
|------|------|
| CO₂ 상한 | 실험 중 2,000ppm 도달 시 즉시 중단 및 전체 환기 (ASHRAE 62.1 기준) |
| 어지러움·두통 발생 | 참여자 중 1인이라도 증상 호소 시 즉시 중단 |
| 에탄올 화기 | 에탄올 사용 구간 화기 금지, 소화기 위치 사전 확인 |
| CO₂ 카트리지 주입 | 1회 주입량 500mL 이하, 5분 간격 분할 주입. CO₂ 2,000ppm 상한이 최우선 중단 기준 |
| 에탄올 사용량 | 100mL 이하, 개방 후 즉시 밀봉 |
| 최대 체류 시간 | CO₂ 1,000ppm 도달 후 최대 15분 이내 종료 |
| 환기 담당 | 안전 감독 1인이 비상 시 창문·문을 즉시 개방할 수 있도록 상시 대기 |
| 최소 인원 | 안전 감독 포함 최소 3인 이상 (단독·2인 실험 금지) |

### 1.2 센서 및 시스템 준비 체크리스트

- [ ] 센서 노드 4개 강의실 모서리 고정 후 전원 인가
- [ ] **MQ 센서 예열**: 최초 전원 인가 후 **최소 5분** 대기 (정량 측정 목적 시 15분 이상 권장). 5분 미만 예열 시 해당 측정값은 "시연용 동작 확인"으로만 해석하고 정량 검증 결과에서 제외
- [ ] MQTT 브로커·백엔드 서버·대시보드 정상 기동 확인
- [ ] 대시보드 전체 노드 `ws_status` 녹색 확인
- [ ] UWB 앵커 좌표 줄자로 실측 후 3D 트윈에 수동 입력
- [ ] 창문 밀폐 전 CO₂ 기준값 측정 및 기록 (외기 기준값, 약 400ppm)
- [ ] S-04용 격자 지점(20개) 바닥 테이프 표시 및 좌표 시트 사전 작성
- [ ] 역할 분담 확정

| 역할 | 담당 업무 |
|------|---------|
| 조작 담당 | MQTT 주입, 서버 제어, CO₂ 카트리지·에탄올 조작 |
| 기록 담당 | 타임스탬프 기록, 스크린샷 저장, 측정값 시트 작성 |
| 안전 감독 | CO₂ 수치 상시 모니터링, 비상 환기 즉시 대응 |

## 2. 실험 순서 및 소요 시간

| 순서 | 시나리오 | 소요 시간 | 시나리오 간 처리 |
|------|---------|---------|--------------|
| 1 | S-06 AI Fallback | 5분 | 서버 재기동 확인 후 진행 |
| 2 | S-07 WiFi 단절 복구 | 10분 | DB 동기화 수 확인 후 진행 |
| 3 | S-03 CO·H₂S 소프트웨어 주입 | 5분 | 창문 개방 불필요 |
| 4 | S-04 UWB 위치 추적 | 15분 | 창문 개방 불필요 |
| 5 | S-05 낙상 감지 | 20분 | 매트 준비, 창문 개방 불필요 |
| 6 | S-02 VOC(에탄올) 반응 | 10분 | 에탄올 밀봉 후 창문 5분 환기 |
| 7 | S-01 CO₂ 점진적 축적 | 30분 | 종료 후 창문 전체 개방 10분 환기 |

> S-06~S-05를 먼저 수행하는 이유: 창문 개방 상태에서도 진행 가능하여 CO₂ 축적 없이 파이프라인·하드웨어 검증을 먼저 완료하고, 이후 가스 실험(S-02, S-01)을 집중 수행한다.

## 3. 검증 기록 데이터 변수

| 필드명 | 타입 | 단위 | 설명 | 해당 시나리오 |
|--------|------|------|------|-------------|
| `scenario_id` | VARCHAR | — | 시나리오 식별자 (S01~S07) | 전체 |
| `trial_timestamp` | TIMESTAMP | — | 시나리오 시작 시각 (UTC) | 전체 |
| `trigger_timestamp` | TIMESTAMP | — | 트리거 이벤트 발생 시각 (임계값 초과, MQTT publish 등) | S-01, S-02, S-03, S-07 |
| `alert_timestamp` | TIMESTAMP | — | 대시보드 경보 표출 시각 | S-01, S-02, S-03 |
| `latency_sec` | FLOAT | 초 | `alert_timestamp` − `trigger_timestamp` | S-02, S-03 |
| `lead_time_min` | FLOAT | 분 | 임계값 도달 시각 − LSTM 경보 발령 시각 | S-01 |
| `co2_at_alarm` | FLOAT | ppm | 경보 발령 시점 CO₂ 농도 | S-01 |
| `voc_iaq_peak` | INT | 0~500 | 에탄올 자극 후 BME680 IAQ 최고값 | S-02 |
| `override_triggered` | BOOLEAN | — | CRITICAL Override 발동 여부 | S-03 |
| `uwb_actual_x` | FLOAT | m | 격자 지점 실제 X좌표 (사전 측정값) | S-04 |
| `uwb_actual_y` | FLOAT | m | 격자 지점 실제 Y좌표 (사전 측정값) | S-04 |
| `uwb_measured_x` | FLOAT | m | 대시보드 표시 X좌표 | S-04 |
| `uwb_measured_y` | FLOAT | m | 대시보드 표시 Y좌표 | S-04 |
| `uwb_error_cm` | FLOAT | cm | √((actual_x−measured_x)²+(actual_y−measured_y)²) × 100 | S-04 |
| `fall_trial_result` | ENUM | — | 각 회차 판정: `TP` / `FP` / `TN` / `FN` | S-05 |
| `fallback_banner` | BOOLEAN | — | Fallback 배너 표출 여부 | S-06 |
| `fallback_alarm_ok` | BOOLEAN | — | Fallback 상태 임계값 경보 정상 동작 여부 | S-06 |
| `buffer_sent` | INT | 건 | WiFi 단절 구간 ESP32 송신 건수 | S-07 |
| `buffer_received` | INT | 건 | 재연결 후 DB 저장 확인 건수 | S-07 |

> `uwb_actual_x/y`는 실험 전 줄자로 측정한 고정값으로 시트에 사전 기재. 실험 중에는 `uwb_measured_x/y`만 기록하면 된다.

## 4. 결과 기록 방법

### 산출물 파일명 규칙

```
S{번호}_{내용}_{YYYYMMDD_HHMMSS}.{확장자}
```

예시:
- `S01_lstm_alarm_20261015_143022.png`
- `S04_uwb_error_log_20261015_150000.csv`
- `S05_fall_confusion_matrix_20261015_152300.xlsx`
- `S07_buffer_log_20261015_151200.csv`

### 시나리오별 산출물

| 시나리오 | 측정 방법 | 산출물 |
|---------|---------|------|
| S-01 | 대시보드 CO₂ 그래프 확인, 경보 발령 시각 기록 | 경보 스크린샷, `lead_time_min` 기록 시트 |
| S-02 | 센서값 임계값 초과 시각(`trigger_timestamp`) → 경보 표출 시각 차이 측정. 기준점은 에탄올 개방 시각이 아닌 센서 수집 시각 기준 | 경보 스크린샷, `latency_sec` 기록 시트 |
| S-03 | MQTT publish 시각 → CRITICAL 표출 시각 차이 측정 | CRITICAL 격상 스크린샷, `latency_sec` 기록 시트 |
| S-04 | 격자 20개 지점에서 `uwb_measured_x/y` 대시보드 확인 후 수기 기록 | `uwb_error_cm` CSV, 3D 트윈 스크린샷 |
| S-05 | 낙상 30회 + 일상 동작 40회(총 70회) 각 회차 TP/FP/TN/FN 기록 | 혼동 행렬 시트 |
| S-06 | 서버 종료 직후 배너 표출 및 임계값 경보 육안 확인 | 배너 스크린샷, 임계값 경보 스크린샷 |
| S-07 | `buffer_sent` vs `buffer_received` 비교 | DB 저장 건수 CSV |

## 5. Pass / Fail 판정 기준

| 시나리오 | Pass | Fail | 완화·주의 사항 |
|---------|------|------|-------------|
| S-01 | 경보가 임계값 도달 **2분 이상** 전 발령 | 도달 후 경보 또는 미발령 | PRD 목표(3~5분)보다 완화. 강의실 CO₂ 상승 속도가 실제 탱크보다 느려 리드타임 절대값이 다를 수 있으므로 프로토타입 단계에서는 "선제 예측 동작 여부" 확인에 집중 |
| S-02 | 센서 임계값 초과 수집 후 **3초 이내** 경보 표출 | 3초 초과 또는 미표출 | 측정 기준점은 에탄올 개방 시각이 아닌 `trigger_timestamp` 기준 |
| S-03 | MQTT publish 후 **3초 이내** CRITICAL 격상 | 3초 초과 또는 가중치 계산 후 판정 | — |
| S-04 | 20개 지점 평균 오차 **±50cm 이하** | 평균 오차 ±50cm 초과 | PRD 목표(±30cm)는 최종 도전 목표. 프로토타입 Pass 기준은 ±50cm. 미달 시 앵커 배치 최적화 방향 분석 후 보고 |
| S-05 | 낙상 감지율 ≥ 80%, 오경보율 ≤ 20% | 감지율 80% 미만 또는 오경보율 20% 초과 | 총 70회는 통계적 신뢰도가 낮으므로 결과는 "프로토타입 동작 확인" 수준. 공개 데이터셋(UR-Fall, UP-Fall) 오프라인 평가로 보완 |
| S-06 | Fallback 배너 표출 + 임계값 경보 정상 동작 | 미전환 또는 배너 미표출 | — |
| S-07 | 버퍼 용량 범위 내 송신 건수 전량 DB 반영 | 버퍼 미초과 구간 데이터 유실 | FIFO 작동으로 인한 오래된 데이터 삭제는 설계 의도이므로 Fail 아님 |

> Pass 기준 미달 시 원인 분석 및 개선 방향을 결과 보고서에 포함한다. PRD 목표값과 프로토타입 Pass 기준이 다른 항목(S-01, S-04, S-05)은 발표 시 기준 차이를 명시적으로 구분하여 설명한다.
